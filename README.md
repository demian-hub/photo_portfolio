# Still photography

Next.js + React + SQLite로 구현한 개인 PC 운영용 포토그래퍼 포트폴리오입니다. 요구사항은 `agents.md`, 시각 방향은 `DESIGN.md`를 참고하세요.

## 로컬 실행

Node.js 24 이상을 사용합니다. SQLite는 Node.js 내장 `node:sqlite`를 사용하므로 별도 DB 서버가 필요 없습니다.

```powershell
npm.cmd install
npm.cmd run setup:admin
npm.cmd run build
npm.cmd run start
```

- 홈페이지: http://127.0.0.1:4173
- 관리자: http://127.0.0.1:4173/admin
- 관리자 아이디와 무작위 초기 비밀번호: `.local/admin-access.txt`
- 이미 관리자 계정이 있으면 `setup:admin`은 계정과 비밀번호를 변경하지 않습니다.
- 개발 시 `npm.cmd run dev`를 사용합니다. 실행 중인 서버를 먼저 종료하고 실행하세요.
- 이 PC에서는 3000번 포트에 바인딩할 수 없어 4173번 포트를 기본값으로 지정했습니다.
- Windows에서는 실행 중인 프로덕션 서버가 빌드 파일을 잠글 수 있습니다. 서버를 종료한 후 다시 빌드하고 실행하세요.

## 포함 기능

- 반응형 단일 페이지, 분야별 2장씩 10장, 분야 필터, 원본 비율 확대
- 네이티브 dialog를 이용한 키보드 포커스 관리, Escape 닫기, 열었던 버튼으로 포커스 복귀
- 한글 및 영문 폰트와 샘플 이미지를 로컬 제공, Next.js 이미지 최적화
- 문의 폼의 필수 항목·연락처·날짜·길이 검증, 항목별 오류와 오류 요약
- SQLite 문의 저장, 접수 번호, 전송 중 중복 클릭 방지, 기본 반복 접수 제한
- 비밀번호 scrypt 해시, 무작위 세션 토큰의 SHA-256 해시 저장, 8시간 만료
- 관리자 로그인·로그아웃, 문의 조회·검색·필터·페이지 이동, 상세 및 상태 변경
- 관리자 API 인증, 변경 요청의 출처 검사, HttpOnly/SameSite 쿠키, 기본 응답 보안 헤더

## 콘텐츠 교체

- 사진: `public/images/*.jpg`를 실제 공개 가능한 작업물로 교체
- 제목·촬영분야·이미지 설명·크롭 위치: `lib/content.js`
- 히어로·작가 소개·푸터: `app/page.js`
- 모든 샘플 사진 출처: `public/images/sources.json`
- Still은 임시 스튜디오명입니다. 작가명, 활동 지역, 연락처, SNS를 실제 정보로 교체하세요.
- 샘플 표시 문구는 실제 작업물로 모두 교체한 뒤 제거하세요.
- 개인정보 안내는 초안입니다. 실제 공개 전에 운영자·수집 목적·보관 기간을 확정하고 `app/privacy/page.js`, `components/InquiryForm.js`, 접수 동의 버전을 함께 갱신하세요. 자동 삭제 기능은 포함되지 않습니다.

## 데이터와 백업

기본 DB 경로는 `data/portfolio.sqlite`입니다. 관리자 비밀번호는 DB에 해시로만 저장되며, 초기 로그인 안내 파일에는 원래 비밀번호가 있으므로 안전하게 보관하세요. `data`, `.local`, `backups`는 Git에서 제외됩니다.

```powershell
npm.cmd run backup
```

SQLite 온라인 백업 API로 일관된 DB 스냅샷과 이미지 사본을 `backups/<시각>/`에 저장합니다. 문의 DB에는 개인정보가 포함되므로 백업도 비공개로 보관하세요.

복구 시 서버를 종료하고 기존 `data` 폴더를 별도 경로에 보관한 후, 백업의 `portfolio.sqlite`를 새 `data/portfolio.sqlite`로 복사합니다. 서버가 종료된 상태에서 새 폴더를 사용하는 방식으로 오래된 WAL 파일이 섞이지 않게 합니다. 이미지도 백업에서 복구하고 서버를 다시 실행합니다.

## 개인 PC에서 외부 공개

현재 서버는 `127.0.0.1`에 바인딩하며 로컬에서만 접속할 수 있습니다. 외부 접속·도메인·HTTPS·공유기 설정은 적용하지 않았습니다.

실제 공개에는 본인 도메인 또는 터널 서비스의 주소가 필요합니다. 도메인을 확보한 후 다음처럼 구성합니다.

1. 작가 실제 정보, 사진, 개인정보 안내를 완성합니다.
2. `.env.example`을 `.env.local`로 복사하고 `SITE_URL=https://실제도메인`, `COOKIE_SECURE=true`를 설정합니다.
3. 같은 PC의 HTTPS 리버스 프록시 또는 HTTPS 터널이 `127.0.0.1:4173`으로 연결하도록 설정합니다.
4. 직접 공개 방식을 쓸 경우 도메인 DNS·공유기·방화벽을 해당 프록시에 맞게 설정합니다. 데이터 폴더를 정적 파일 경로로 노출하지 않습니다.
5. `npm.cmd run build` 후 서버를 다시 실행하고, 외부 네트워크에서 접속·문의·관리자 로그인을 검증합니다.
6. PC 전원·절전·재부팅 후 자동 실행과 정기 백업을 설정합니다.

로그인 후 자동 실행용 예시는 `scripts/start-site.ps1`에 있습니다. Windows 작업 스케줄러에서 해당 스크립트를 실행하도록 연결할 수 있습니다. OS 자동 실행·절전·방화벽 설정은 현재 변경하지 않았습니다.

도메인 기반 프록시를 사용하는 경우 `ops/Caddyfile.example`을 참고할 수 있습니다. Caddy 설치·실행은 자동으로 수행하지 않습니다. 공개 후 문의 알림은 제공되지 않으므로 관리자가 직접 접속해 확인합니다.
